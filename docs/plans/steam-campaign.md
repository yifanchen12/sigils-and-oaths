## 完成标准

1. **可玩闭环**：新游戏、教程、选项、章节、战斗、奖励、营地、选择、终章、结局、回顾均有可达入口；失败可重试，退出再开可恢复；旧版遭遇战继续可用。
2. **正文**：至少100,000个独立中文汉字，来自可达剧情、支线、事件、人物与世界档案。按稳定文本ID去重，同文重复不计入；排除提示词、设计稿、程序、商店宣传、按钮和规则。另报全部分支总量与单条通关路线实际可读量。重复率报告不能代替编辑审读。
3. **内容规模**：计划10章、约20场核心战斗；3位指挥官与6位部队队长的支线，3种受抉择影响的结局。正文预算主线60,000、人物22,500、营地/事件12,500、档案10,000，实际以可读性与接入量为准，不靠模板扩写凑数。
4. **统一美术**：成年角色正常比例、清晰线稿与赛璐璐阴影；同角色发色、脸型、装备、纹章一致；地图、卡面、对话、档案与菜单共享配色。保留原创来源与提示词，实机验证小尺寸辨识及遮挡。关键姿态不等同完整骨骼动画。
5. **逻辑与平衡**：规则回归零失败；每章成功/失败/重试/分支可达；存档往返、损坏恢复、较新版本保护；先后手与地图分层自对弈，记录种子、回合、行动、终止原因。胜率异常触发复核，不能用单一AI互打宣称平衡。完整人工试玩与外部试玩反馈仍是发布门槛。
6. **构建**：独立Windows发行包在不依赖项目引擎路径的情况下启动、存读档、通关；低分辨率、窗口/全屏、输入、音量、文本阅读、长时间运行与错误日志检查。
7. **Steam准备**：真实实机截图、商店文案、胶囊图、预告片、系统需求、内容调查与AI预生成披露草稿、依赖/字体/素材授权清单；页面承诺与构建一致。账号、App ID、缴费、税务银行与Valve审核为外部步骤；不伪称通过审核。

## 能力与文件边界

| 能力 | 文件与职责 | 验收 |
| --- | --- | --- |
| 九角色姿态 | `art_library.gd` 图集；`main.gd`展示来源；`board_view.gd`有界时间线；`tests/test_*poses.gd` | 透明边缘、左右朝向、技能、反击、清理、规则不重复结算 |
| 世界与人物档案 | `data/narrative/codex.json` 稳定ID及正文；`scripts/lore_book.gd` 原生阅读界面；`war_council.gd`入口 | 全档案可点开、滚动、键盘关闭；不泄漏战斗输入 |
| 剧情执行 | `scripts/story_runner.gd` 图状态；`data/narrative/chapters/*.json`节点与文本；`story_view.gd`阅读/选择 | 有效跳转、终止、条件、一次性选择结果、回看不重复奖励 |
| 战役 | `scripts/campaign.gd`进度/关卡/结果；`data/campaign.json`关卡与成长；`main.gd`衔接现有战斗 | 剧情到战斗再回剧情、胜败重试、结局 |
| 存档 | `scripts/campaign_store.gd`版本/临时写/备份/恢复；独立于套牌存储 | 真实退出重开与异常测试 |
| 统一视觉 | `docs/art-direction.md`角色/阵营/界面规范；现有美术清单与原生新素材 | 逐屏实机校对，不批量覆盖已认可画作 |
| 测试与发行 | `tests/`行为测试；`tools/audit_narrative.py`字数/引用/重复；`docs/release/`发行清单；导出预设 | 结果带版本与范围，未验证项明确标出 |

`battle.gd`继续是战斗唯一规则源。剧情不得直接改写卡牌基础数值；关卡参数通过明确配置接入。剧情、美术阶段不修改兵种平衡，平衡调整单独留前后指标。

## 最小接口

- 档案：`version`, `entries[{id,category,title,subtitle,portrait,summary,body}]`，UTF-8；正文数组按段阅读，未知肖像用纯文字。所有条目由档案目录可达。
- 剧情：节点以ID引用，类型仅对白、选择、战斗、结束；对白稳定line_id；选择是结构化flags写入，无eval。变量与UI分离。保存当前节点及已确认选择，拒绝不存在的目标。
- 战役：启动关卡返回合法的地图、英雄、牌组、种子与目标；战斗完成只接受一次结果，失败不发奖励；先独立测试，再接入Main。
- 存档：返回 `{ok, message, state?}`；写入失败保留旧档并显示错误；较新版本不得覆盖。

## 实施顺序与检查点

1. 收尾本地动作：解析导入 → 原生动作测试 → 实机图集 → 素材来源与变更说明。
2. 编写世界基线、人物档案、首章梗概；档案独立加载/审计，再接菜单。此阶段只计已进入游戏的档案正文。
3. 独立验证剧情图、战役状态和存档，再组装第一章，最后接主菜单。做到一章可从开始走到结算并恢复存档。
4. 逐章制作：关卡机制、正文、分支、营地、背景、人物表现、可达性、通关回归。章节内容不一次生成十万字后再硬接。
5. 全内容完成后进行分层平衡、难度与长局测试、可用性试玩，修问题而非继续堆功能。
6. 冻结内容、导出构建、完整通关、素材审计、Steam商店准备。未达到上述标准不结束持续目标。

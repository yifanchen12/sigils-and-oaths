# 单槽自定义套牌与保存

延续之前暂缓的自由组牌；先做一个本地套牌槽，不扩展账户、云同步或多存档。

## 接口与职责

- DeckData提供纯数据校验：30张、每种0–4张、至少1张部队、只接受已知可组牌ID和有限整数数量；后手专属牌不能组入。
- DeckStore读取/保存版本1的JSON卡牌数量，重建固定自定义套牌身份。临时文件写入并检查后保留最后一个有效备份，再重命名；损坏文件尝试备份，不加载Resource/脚本。不覆盖更高版本存档。
- Battle构造函数末尾增加可选己方自定义定义参数；每场保存独立套牌快照，不修改共享Resource。无效输入不能进入自定义规则牌库，防御性回退有日志；UI提前阻止无效自定义开战。
- 原生DeckEditor只编辑草稿，保存成功后才更新战前菜单的自定义选项。可从三套预组牌复制。保存不重置正在进行的对局，重新开战才使用。自定义己方对阵均衡AI；三套预组牌仍沿用原先镜像对阵。
- 组牌仅从战前菜单进入；规则/图鉴/组牌与战前菜单均暂停本地AI和倒计时。取消编辑不改变已保存套牌。

## 验收

1. 纯校验与备份/损坏/未来版本/失败写入测试；无效保存不覆盖有效文件。
2. 新Godot进程读回上个进程写入的套牌；配置与数量相同。
3. 实际鼠标增减、30张限制、每种上限、保存、重开选择与图鉴张数；当前战斗在编辑期间不变。
4. 自定义牌库实际发牌计数和原预组牌回归；真实组牌截图与窗口布局检查。测试使用独立工作区路径，不覆盖玩家真实套牌文件。

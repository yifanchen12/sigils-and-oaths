# 持续迭代计划

授权：用户于 2026-10-25 要求持续开发，使用当前五小时额度，明确包含美术、地图、克制、地理加成、英雄指挥官技能及环境卡。此文记录执行顺序，不另设重复审批。

## 复用与边界

- 延用 Battle 的唯一规则入口、合法行动枚举、CardData Resource、原生 Control 界面和现有 AI。
- 现有基础版已通过 75 项规则检查、80 项图形检查与 12 场自动对局；新规则必须保持非法操作原子性、卡牌区域唯一性和友军相邻部署。
- 所有代码、资源和验证产物仍限制在 card-tactics/，不修改相邻项目。

## 第一轮：地理、环境、英雄

1. 地图以 Resource 数据驱动，至少三张可选手工地图。保留 8×6 网格以复用输入和可读布局，重点改变路线与资源点分布。
2. 地形包括森林、山地、道路、河流/桥梁、高地与遗迹。兵种移动费用和地形战斗加成有统一查询函数；UI 与 AI 共用这些函数。
3. 明确克制表。步/枪/骑三角保留；远程与法师通过射程、地理与针对性机制形成有解释的取舍，不硬加覆盖所有兵种的复杂循环。
4. 三名可选指挥官，各有明确的被动、消耗法力的主动技能和冷却。主动技能纳入相同合法操作入口，AI 同样遵守。
5. 环境卡加入牌库：暴雨、浓雾、烈日、寒潮等，以明确期限与可见状态改变移动/射程/伤害。新环境替换旧环境，计时按双方完整轮次定义。
6. 扩展 tests/test_battle.gd，覆盖地形路径费用、地形收益、英雄技能消耗/冷却、环境替换/到期、三地图完整 AI 对局。

新增数据职责：scripts/map_data.gd + data/maps.tres、scripts/hero_data.gd + data/heroes.tres。地图和英雄选择 UI 与 main.tscn/main.gd 连接；battle.gd 消费配置，不读取 UI。

## 美术目标与制作

- 保留深靛蓝、玉青、赤陶红与旧金的阵营和界面语义。
- 原创手绘奇幻：有明确光照的油画/水粉质感、清楚面部和武器轮廓、低对比背景，避免直接使用参考游戏素材或复制具体角色。
- 首个代表目标：青绿披风与旧金护甲的指挥官半身肖像，脸部在 72px 高度仍可辨识。
- 图片仅负责插画；卡牌文字、费用、数值、格线、高亮与交互保持原生绘制。
- 生成原图保留在 assets/art/source/，实际消费版本在 assets/art/；记录工具、完整提示词、尺寸、来源、裁切和引擎内检查结果。
- 由用户本轮授予的自主美术决策授权，先在实际画面确认代表目标，再扩充同风格卡牌/英雄和地图背景。

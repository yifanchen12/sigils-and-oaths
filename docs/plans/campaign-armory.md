# 战役军备编成

战前军需会交换一张起手牌。战役军备让玩家在随后几场战斗继续使用已经选定的牌。每关仍从原定军势出发，三个换牌位按章节进度开放。

1. **规则验收**。前两章、第四章、第七章完成后依次开放 1–3、4–6、7–10 费位。候选来自回澜契令。每个位置可留空。选中的牌替换己方牌库中一张同为部队或同为战术的牌，优先费用接近。军备安排在起手之后的第 2、5、8 次牌库抽牌，原定起手和敌方开局保留。牌库始终符合 30 张与单卡上限。
2. **存档验收**。战前保存用同一份换牌算法校验。战斗快照仍记录实际牌序和牌区。旧档以空编成打开，进度照常开放卡位。章节重走从该章之前的军备状态继续。测试无效配置、备份恢复、较新版本保护和正在进行的旧版战斗。
3. **界面验收**。从战前简报打开军备，逐位查看画面、卡牌效果、换下的牌和投送次序。取消可撤销草稿。检查小窗口、读档、真实手牌出牌和战斗回返。
4. **构建验收**。在原定与军备编成上重跑有代表性的关卡，记录实际出牌、胜负与长局。使用一条经过实际战斗的连续路线检验章节进度。导出 Windows 预览包并在打包内容上验证。

规则由 `campaign_armory.gd` 计算。战斗入口、预览和存档使用同一函数。选中的卡牌 ID 写入战役和已完成章节的记录，由 `campaign.gd` 还原。界面通过 `campaign_session.gd` 提交完整草稿，成功后才更新运行中的军备。玩家自定义的自由对战套牌仍由原来的构筑系统保存。

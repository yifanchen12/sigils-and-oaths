# 完整战斗存档

在首章已接线的基础上完成发行目标中的中途保存；现阶段仅无窗口纯逻辑验证，不运行图形场景。

## 复用与边界

- 复用Battle的唯一权威状态及CampaignStore临时写、有效备份和未来版本保护，不复制战斗规则。
- 新建BattleSnapshot处理纯数据。保存双方牌库/手牌/弃牌的顺序与实例ID、部署牌关联、单位顺序/位置/数值/技能与援护/定身/移动历史、指挥官显示身份、双方资源/疲劳/技能冷却、地形改变、天气及剩余时间、回合/当前行动方/胜负/战报/next_id。
- 保存RNG的seed和state为十进制字符串，避免JSON双精度损失64位整数；恢复后不再次抽牌或触发回合开始。战斗资源签名和版本不匹配时保护文件，不静默替换规则。
- 不保存动画、选中目标、悬停、信号连接、场景节点与AI协程；载入重建视图，并根据当前行动方重新启动唯一AI执行序列。
- CampaignStore升级到v2，v1迁移为不含进行中战斗的检查点。战斗必须绑定当前章节/剧情battle节点/关卡配置，不能把另一地图的快照塞进当前剧情。
- 自动槽保存已完成的规则动作；每5秒保存计时，进入菜单及正常窗口退出前立即保存。动画期间保存的也是已经结算的数据，不重播结算。意外终止最多丢失本次自动保存间隔的计时，写入失败必须可见，退出失败不直接关闭。
- 切换自由对战保留战役模型；新战役显式替换，读档后的旧动作失效。现有一个自动槽，不在此步增加云同步或多槽界面。

## 验收顺序

1. 快照JSON往返及畸形输入：状态相等、无别名、ID/坐标/牌区/守卫顺序/版本检查，失败不改运行中的战斗。
2. 恢复前后执行相同行动和计时，逐步比较状态及下一段RNG输出；覆盖英雄/部队技能、天气、疲劳、地形修改、换位、残血与死亡。
3. v1迁移、v2中途保存、关联关卡验证、损坏恢复及未来版本保护；两个独立进程验证保存、退出、读回并继续同样结果。
4. Main接入动作/计时/菜单/退出保存与AI恢复，仅做语法检查。新增原生UI场景验收仍待允许后执行，不能用模型测试替代。

完整战斗存档可用不等于完整战役已完成。正常难度通关、后续章节、平衡、音频、发行构建等目标保持不变。
